# Fixture provenance audit: Pen.dev-authored material in the repo

**Date:** 2026-09-26. **Leaf:** `jxrS92` (parent `PMyYps`). **Author:** agent `fixture-audit`.
**Scope:** every file `git ls-files` reports, plus git history. Pen.app 1.2.14 (`/Applications/Pen.app`,
`CFBundleShortVersionString` 1.2.14) is the reference for what Pen.dev ships.

This is a statement of provenance, not legal advice. It says where each file came from and what the
evidence is. Whether a given file counts as copyrighted by Pen.dev is a question for Ben; those
questions are in [Open questions](#open-questions).

## Findings

1. **`Tests/WoodcaseTests/Fixtures/shadcn.lib.pen` is a verbatim copy of Pen.app's bundled shadcn
   design-system library.** When it was added (`fe307a0`, 2026-03-24), its JSON was equal to
   `app.asar:/out/data/shadcn.lib.pen` in Pen.app 1.2.14: same version (2.8), same 278 node ids, same
   150 names, same 43 text strings, same 28 variables and 3 theme axes. The only changes since then are
   the 2.17 migration (`043e286`, `5b82ed4`, both 2026-08-29). The file is not byte-equal to the bundled
   one today only because it was migrated to 2.17. The top frame is named `shadcn: design system components`.
2. **`Tests/WoodcaseTests/Fixtures/banking.pen` is derived from Pen.app's shadcn "design kit" starter
   document** (`app.asar:/out/data/pencil-shadcn.pen`). It reuses that document's prompt node id
   `j4hLC` (same `x` 3053, same `model: "cursor-composer"`) and its first frame's id `nSNTs` (same
   position `3053,-10`, renamed from `dashboard-utility` to `banking-home`). Its `variables` and
   `themes` blocks are equal to the library's. It imports the library as `pencil:shadcn.lib.pen` and
   places library components through `V:`-prefixed refs (5 direct `V:` refs; the rest of its refs
   point at its own components, which wrap library ones). The prompt text was rewritten to
   *"Build the hero screen for a modern banking app in `banking`…"*, and the screen content (greeting,
   balance card, transactions) was generated by Pen's in-app AI agent from that prompt. So the file
   mixes Pen's template scaffolding, Pen's tokens, and screen content that Pen's agent generated for Ben.
3. **`banking-home-light.png` and `banking-home-dark.png`** (`9c87f81`, 2026-03-24) are Pen.app
   exports of finding 2 rendered with finding 1's components. They are the MAE references for
   `PenBankingAppTests`.
4. **Nothing else tracked matches Pen's bundled samples.** 120 of the 132 tracked `.pen` files share no
   ids, no names (≥4 chars), no text (≥6 chars) and fewer than five variables with any of Pen's twelve
   bundled documents. Of the other twelve, two are findings 1–2. Five (`addressing.pen`,
   `addressing-nested-instance.pen`, `woodcase-app.pen` and the two `project/` prototypes) share only
   generic words (`Button`, `Header`, `Title`, `9:41`, `Settings`). The five `blur*.pen` files share only the id `bi8Au` plus the name `Frame`. Those
   come from Pen's blank-document template `pencil-new.pen` (one 800×600 white frame). That means
   those fixtures were started from File › New in Pen.app. There is no copied design content in them.
5. **`woodcase-app.pen` is original.** It is a pencil-collection app ("Blackwing 602",
   "Faber-Castell 9000", "24 pencils"). Its tokens, component names and copy are its own, and it shares
   no ids with any Pen sample. Two caveats are recorded here because they are not Woodcase-authored,
   though they are not Pen.dev's either:
   - Its 8 images (`Tests/WoodcaseTests/Fixtures/images/generated-17742*.png`) are **JPEGs made by
     Google generative AI**. Each carries a C2PA manifest reading "Created by Google Generative AI.",
     "Applied imperceptible SynthID watermark.", with digital source type `trainedAlgorithmicMedia`.
     The epoch-millisecond names (2026-03-23 15:03–15:18 CDT) fit Pen's in-app image generation. Pen
     1.2.14 lists `google/gemini-2.5-flash-image` as a model. That the images came through Pen is an
     inference; that they came from Google's model is recorded in the files themselves.
   - The Lab screen has the text **"Visit Pencil.dev"**. It shows up again in `golden/ScreenLab.tsx.golden`.
6. **The Pen spec files in `local/` have never been tracked.** `local/` is in `.gitignore`, and
   `git log --all -- 'local/*'` returns no commits. None of their lines (≥35 characters, with comment
   and markdown markers removed) shows up in any tracked file.
7. **Pen.app bundles none of the icon fonts in the repo.** Pen.app's only bundled font is
   `out/assets/font/pencil.woff`. The repo's lucide, feather, Phosphor and Material Symbols TTFs
   (`ea6718e`, `8ef9f97`) come from those projects, and their licenses are in `LICENSES/`.
8. **Git history holds exactly what HEAD holds, plus 46 more generated images.** No `.pen` file
   was ever deleted from history (every `.pen` path in history is in HEAD). Commit `8ef9f97`
   deleted 46 more `images/generated-*.png` files, which are the same kind as finding 5 and are still
   reachable in history. Removing findings 1–3 from HEAD will leave them in every commit since
   `fe307a0`. The remote is `git@git.mattebox.com:ben/Woodcase.git`, which is self-hosted.
9. **Another repo reads these files.** `../RapidPro/Tests/RapidProTests/Fixture/BankingTextFillTests.swift`
   loads `banking.pen` and `shadcn.lib.pen` from the Woodcase checkout by relative path.

### What coverage they provide that nothing else does

- **An import at library scale.** The library has 87 reusable components, 28 variables and 3 theme
  axes (`Mode` × `Base` × `Accent`, 2 × 5 × 8). The host reaches it through `V:` refs. `imports.pen`
  and `parser-imports.pen` are the only other import fixtures, and both are small and never resolved
  against a real library.
- **Ref chains across the import.** A library component that is itself a ref, and descendant
  overrides with slash paths that cross refs. `9c87f81` fixed both against this pair.
- **Per-side strokes and disabled children in layout.** Library icon buttons contain a disabled
  "Button" label that must not be measured. `9c87f81` fixed this against this pair too.
- **A real-world render compared with Pen.app** in two themes, including icons (lucide through the
  library), shadows and effects. The threshold is MAE < 40, which is loose.
- **A document shaped like an agent's work.** It has a prompt node, all top-level frames are
  definitions, and placed screens are themed refs. The CLI, scripting and viewer tests, and the
  editor docs, are written against this shape.
- **The largest non-ref top-level frame**, used for the `shot` performance number.

## Replacement plan

> **Outcome (2026-09-26, leaf `vVehlp`).** Rulings 1–2 changed the plan below: `banking.pen` is kept
> and repointed, so there is no `wallet.pen`. `shadcn.lib.pen` is replaced by
> `Fixtures/kit.lib.pen`, written by `scripts/gen-kit-fixture` (89 components, 25 tokens,
> `scheme` × `tint` × `contrast`); `banking.pen` imports it as `V` → `kit.lib.pen` (Pen resolves
> the relative path headless; it rewrites `./kit.lib.pen` to `kit.lib.pen` on save), carries the
> kit's tokens, and places its screens as `scheme` day/night with `tint: moss`. The references
> were re-exported with headless `pen interactive` (pen CLI 0.3.5). The `pencil:` key form stays
> covered by the synthetic cases in `PenImportResolverTests`. The appendix scripts are filed as
> `scripts/pen-provenance-check`, which gates on distinctive overlaps only. The new library's
> two-deep ref chain exposed a `PenRefExpander` bug (an outer link's descendant overrides were
> lost); it scored MAE 4.68 under the old threshold of 40. `PenBankingAppTests` now allows 8.

The goal is equal coverage from files with no Pen.dev lineage. The replacement should be *generated*,
not drawn: a deterministic script under `scripts/` whose output anyone can re-create, which gives a
clean provenance story. It should also avoid Pen's token vocabulary (`--background`, `--primary`,
`--sidebar-*`, `Mode/Base/Accent`), shadcn's component taxonomy and names, and Pen's design-kit
starter layout.

### Proposed fixtures

- **`Fixtures/kit.lib.pen`**, a new component library made by `scripts/gen-kit-fixture` (Python,
  standard library only, the same style as `scripts/pen-oracle`). Target parity with what the tests
  need:
  - at least 80 reusable components across about 10 families (buttons in sizes/tones, chips, fields,
    toggles, list rows, tabs, a table built from row/cell components, cards, a nav bar, a sheet);
  - variables under its own names, for example `ink`, `paper`, `accent`, `hairline`, `radius-*`,
    `space-*`;
  - three theme axes with different names and a different product of values, for example
    `scheme: day|night` × `tint: slate|sand|moss|clay` × `contrast: normal|high`, so the
    multi-axis resolver still sees three axes and more than 2 values per axis;
  - components built to hit the regressions: per-side strokes (a bottom-only divider row); a
    disabled child inside an icon button; a component that is itself a ref (ref chain); nested
    instances with slash-path descendant overrides; shadows and blur effects; lucide icons;
  - one large top-level frame, not a ref, as the `shot` performance target.
- **`Fixtures/wallet.pen`** (any original name), a host app that imports `./kit.lib.pen` under alias
  `V`. It is shaped like `banking.pen` in the ways the tests read: all top-level frames reusable, one
  screen definition plus two placed themed refs (`/ Day`, `/ Night`), a repeated-row section the
  scripting example can clone (`…/transactions-section` equivalent), a status bar, and a prompt node
  whose text Ben writes. Every content string is original. The generator can emit this file too, or
  Ben can draw it in Pen.app, as long as no design kit and no AI agent are used.
- **Reference PNGs** `wallet-home-{day,night}.png`: exported from Pen.app by opening the two generated
  files. Rendering an original file in Pen.app is how every other MAE reference in the repo was made
  (`layout-*`, `render-*`, `blur*`, `woodcase-app-*`). The PNG is Pen's rasterization of Woodcase's
  content. Whether that is acceptable is open question 3. First check that Pen.app resolves a relative
  `./kit.lib.pen` import (`imports.pen` uses that form, but no reference was ever rendered through
  one). If it does not, flatten the library into the host for the export only.
- **The `pencil:` key form.** Import-resolver tests keyed on `"pencil:shadcn.lib.pen"` should keep one
  small synthetic case with a `pencil:`-style key so that string form stays covered. It should use a
  made-up library name, not Pen's.

`asar.py`: lists or extracts an Electron `app.asar` without `npx asar`.

```python
import json, struct, sys, os, re
f = open(sys.argv[1], 'rb'); _, hsize, _, jlen = struct.unpack('<IIII', f.read(16))
header = json.loads(f.read(jlen)); base = 8 + hsize
def walk(node, path):
    for name, n in node.get('files', {}).items():
        full = path + '/' + name
        yield from (walk(n, full) if 'files' in n else [(full, n)])
if sys.argv[2] == 'list':
    for full, n in walk(header, ''): print(n.get('size'), full, 'UNPACKED' if n.get('unpacked') else '')
else:  # extract <outdir> <regex>
    out, pat = sys.argv[3], sys.argv[4]
    for full, n in walk(header, ''):
        if re.search(pat, full) and not n.get('unpacked') and 'offset' in n:
            f.seek(base + int(n['offset'])); dst = out + full
            os.makedirs(os.path.dirname(dst), exist_ok=True); open(dst, 'wb').write(f.read(n['size']))
```

`compare.py <dir-of-Pen-samples>`: for every tracked `.pen`, counts shared ids (≥4 chars), names
(≥4), text `content` (≥6) and variable names against each Pen sample. It reports a sample when any id
is shared, or at least 2 texts, 5 variables or 5 names are shared. Run it from the repo root with the
sandbox disabled, because it calls `git ls-files`.

```python
import json, sys, glob, os, subprocess
def feats(p):
    d = json.load(open(p)); ids, names, texts = set(), set(), set()
    def w(n):
        if isinstance(n, dict):
            if isinstance(n.get('id'), str) and len(n['id']) >= 4: ids.add(n['id'])
            if isinstance(n.get('name'), str) and len(n['name']) >= 4: names.add(n['name'])
            if isinstance(n.get('content'), str) and len(n['content']) >= 6: texts.add(n['content'])
            for v in n.values(): w(v)
        elif isinstance(n, list):
            for v in n: w(v)
    w(d); vars_ = set(d.get('variables', {}).keys()) if isinstance(d, dict) else set()
    return dict(ids=ids, names=names, texts=texts, vars=vars_)
ref = {os.path.basename(p): feats(p) for p in sorted(glob.glob(sys.argv[1] + '/*.pen'))}
for f in filter(None, subprocess.check_output(['git', 'ls-files', '*.pen']).decode().split('\n')):
    F = feats(f); hits = []
    for rn, R in ref.items():
        s = {k: len(F[k] & R[k]) for k in F}
        if s['ids'] or s['texts'] >= 2 or s['vars'] >= 5 or s['names'] >= 5: hits.append((rn, s))
    print(f, {k: len(v) for k, v in F.items()}, '->', hits or 'no overlap')
```
