# Phase 4: Visual Regression via WebView

## Context

Phase 3 is complete (95 tests). ReactEmitter generates self-contained React + Tailwind output: `components/*.tsx`, `pages/*.tsx`, `ThemeProvider.tsx`, `lib/cn.ts`, and `theme.css`. But we have no way to verify that this generated code *looks right* — that the JSX + CSS actually produces the same visual output as Woodcase's own pixel renderer. Phase 4 closes this loop: render the generated React in a WebView, screenshot it, and MAE-compare against Woodcase's CGImage render.

## Architectural Decisions

**D1: WKWebView-based test harness.** Use `WKWebView` (macOS-only, `#if canImport(WebKit)`) to load generated React as an inline HTML page. Locally-bundled React + Tailwind JS keeps the harness self-contained with no npm build step and no network dependency. The harness is a test utility, not production code.

**D2: Async screenshot capture via `WKWebView.takeSnapshot`.** The harness loads HTML, waits for a JS `window.__READY__` signal (set by a `useEffect` after React renders), then captures via `takeSnapshot(configuration:)`. Uses Swift concurrency with a `withCheckedContinuation` bridge for the callback-based WebKit API.

**D3: ReactHarnessBuilder assembles HTML from GeneratedFile output.** Takes the `[GeneratedFile]` from `ReactEmitter.emit()`, inlines component + page + theme CSS into a single HTML document. Loads React, ReactDOM, Babel standalone, and Tailwind from local JS files bundled as test resources in `Tests/WoodcaseTests/Fixtures/js/`. No filesystem write needed — everything is passed as an HTML string to `loadHTMLString`.

**D4: Reuse existing MAE infrastructure.** `PenSnapshotTestHelpers.meanAbsoluteError(between:and:)` already handles CGImage comparison with automatic scaling. The WebView screenshot produces a CGImage via the snapshot API.

**D5: Looser thresholds than pixel-render tests.** Font rendering (Core Text vs browser), anti-aliasing, and sub-pixel rounding will produce differences. Target MAE < 15 for shape-heavy components, < 25 for text-heavy screens. These are significantly looser than the render-pipeline tests (MAE < 5–8) but still catch layout or color regressions.

**D6: `@MainActor` isolation for WebView tests.** WKWebView requires main thread. Test methods will be `@MainActor` annotated. The harness itself will be a `@MainActor` class.

## Key Risk

**Unitless CSS variables.** ThemeEmitter currently emits raw numbers for sizing variables (e.g., `--card-radius: 16` without `px`). Tailwind's `var()` references may not work unless the values include units. This will surface in Chunk 3/4 when visual comparison reveals mismatches, and we'll fix ThemeEmitter at that point.

**WKWebView requires a display.** Headless CI (Linux containers, etc.) can't run WebView tests. Mitigation: tag with `.webViewRegression` so they can be skipped. macOS CI runners with a display (GitHub Actions macOS runners, local dev) work fine.

## Chunks

### Chunk 1: WebViewTestHarness + JS Resources (~4 tests)

Bundle local JS dependencies and build a `@MainActor` harness class that loads an HTML string into `WKWebView`, waits for `window.__READY__`, and captures a screenshot as `CGImage`.

**JS Resources:**
- Download pinned versions of `react.production.min.js`, `react-dom.production.min.js`, `babel.min.js`, and `tailwindcss.js` (standalone browser build) into `Tests/WoodcaseTests/Fixtures/js/`
- These are already covered by the existing `.copy("Fixtures")` resource bundle in Package.swift
- Total size ~500KB — trivial for test resources

**Implementation:**
- New file `Tests/WoodcaseTests/WebViewTestHarness.swift`
- `#if canImport(WebKit)` guard around the entire file
- Class `WebViewTestHarness` with:
  - `func render(html: String, viewportSize: CGSize) async throws -> CGImage`
  - Internal: create `WKWebView` with given viewport, `loadHTMLString`, use `WKNavigationDelegate` + `userContentController.add(scriptMessageHandler)` for `__READY__` signal, `takeSnapshot`
- New file `Tests/WoodcaseTests/WebViewTestHarnessTests.swift`
- Tests:
  1. Renders trivial HTML (`<div style="background:red; width:100px; height:100px">`) → screenshot is non-nil, dimensions match viewport
  2. Renders HTML with `__READY__` signal → screenshot captured after signal
  3. Renders transparent background → alpha channel correct
  4. Timeout test → returns error if `__READY__` never fires

**Files:**

### Chunk 2: ReactHarnessBuilder (~5 tests)

Build an HTML document from `ReactEmitter` output that can be loaded into the WebView harness.

**Implementation:**
- New file `Sources/Woodcase/CodeGen/ReactHarnessBuilder.swift`
- `public enum ReactHarnessBuilder` with:
  - `static func buildHTML(from files: [GeneratedFile], componentName: String, props: [String: String] = [:], viewportSize: CGSize, jsResourceDir: URL) -> String`
  - Inlines `theme.css` into a `<style>` tag
  - Reads React, ReactDOM, Babel, and Tailwind JS from `jsResourceDir` and inlines them as `<script>` tags (no CDN, no network)
  - Inlines the target component `.tsx` (and any imported components) into a `<script type="text/babel">` block
  - Renders `<ComponentName {...props} />` into `#root`
  - Sets `window.__READY__ = true` via `useEffect` or `setTimeout`
  - Wraps in `ThemeProvider` with default theme (light mode)
- Tests:
  1. Output contains inlined React JS content
  2. Output contains inlined theme.css content
  3. Output contains target component code
  4. Output contains `__READY__` signal
  5. Output sets correct viewport meta tag

**Files:**
- `Sources/Woodcase/CodeGen/ReactHarnessBuilder.swift` — new
- `Tests/WoodcaseTests/ReactHarnessBuilderTests.swift` — new

### Chunk 3: Simple Component Visual Tests (~4 tests)

First real visual comparisons: render simple components (solid fills, basic layout) in both Woodcase renderer and WebView, MAE-compare.

**Implementation:**
- New file `Tests/WoodcaseTests/WebViewRegressionTests.swift`
- Pattern per test:
  1. Parse `woodcase-app.pen` → full pipeline (ref expand, variable resolve, layout, render) → CGImage at 2x
  2. Parse same file → code gen pipeline (analyze, emit) → `ReactHarnessBuilder.buildHTML` → `WebViewTestHarness.render` → CGImage
  3. `PenSnapshotTestHelpers.meanAbsoluteError` → assert below threshold
- Start with shape-heavy components (StatusBar, NavigationBar — mostly fills and layout, minimal text)
- Register test fonts for Woodcase renderer via `TestFontRegistration.registerTestFonts()`
- Tag with `.webViewRegression` (for filtering on headless CI)

**Files:**
