# The `pen` CLI, kicked (2026-08-29)

Author: Claude (Fable 5), at Ben's request mid-session — he found `pen` (0.3.5,
`/opt/homebrew/bin/pen`) and asked what we might borrow. Reproduce every claim with the
commands shown; all need the Bash sandbox off and a one-time interactive `pen login`.

## What it is

Two tools in one binary:

1. **A prompt runner.** `pen --in a.pen --out b.pen --prompt "…" --agent claude` hands
   a design task to a hosted agent (Claude/Codex/Gemini) that drives the same MCP tools
   we use, then writes the file. `--tasks <json>` batches prompts; `--export` renders
   the result; `--usage` writes token cost. Not our concern — it is the thing Woodcase
   is the alternative to.
2. **`pen interactive` — a JS REPL over the MCP tools**, in two modes:
   - `--app desktop`: connects to the running Pen.app and drives *its* document.
   - `--in <file> --out <file>`: **headless** — the full Pen engine (layout, expansion,
     export) without the app.

   Both read tool calls from stdin (`get_app_state()`, `execute({input: "…"})`,
   `save()`, `exit()`), so a pipe works: no TTY needed.

## What we verified

```
printf 'get_app_state()\nexecute({ input: "Insert(document,{type:\"frame\",name:\"Probe\",width:100,height:50,fill:\"#F00\"})" })\nsave()\nexit()\n' \
  | pen interactive --in Tests/WoodcaseTests/Fixtures/expander-nested-ref.pen --out $TMPDIR/probe-out.pen
```

- Headless `execute` ran, printed the same name → id map as the MCP, and `save()`
  wrote a **2.17 file** — with Pen's own normalisation applied (`fontFamily: "Inter"`
  and `fontWeight: "normal"` materialised on a text node that had neither; `x: 0, y: 0`
  on roots). So headless Pen is also a canonicaliser: "what does Pen write for X?" is
  now a command, not a ⌘S.
- **Globals persist across calls in the CLI** ("Global variables (e.g. root) carry
  over to subsequent calls!") — the MCP's documented-but-broken promise works here.
- `printf 'save()\nexit()\n' | pen interactive --app desktop` saved Pen.app's active
  document (`local/tirekick.pen`, 390 KB) to disk. That closes the "Pen never saves"
  gotcha and is how the viewer prototype's `.pen` got filed.
- Authentication is required for *both* modes, even headless on a local file — a
  pen.dev account and network. `PEN_CLI_KEY` exists for CI.

## What we take from it

- **A test oracle.** Headless Pen can settle layout (`Get` visitor with `ctx.bounds`)
  and export PNGs for any fixture, scripted. That turns the MAE fixtures and the
  `.layout.json` fixtures from hand-saved artefacts into generated ones — worth a
  `scripts/pen-oracle` that takes a `.pen` and emits both, run by hand, with its outputs committed
  as fixtures. **Ben's ruling: `pen` is never a test-suite dependency** — it may break
  or vanish, and consumers cannot be made to install and log in — so no test shells out
  to it; tests read the generated files only. Filed as a leaf under the viewer/editor root.
- **A canonical-form check.** `woodcase migrate` claims to write what Pen writes;
  round-tripping a fixture through headless `save()` and diffing is the test. Same
  script.
- **A save verb for the MCP workflow** (already in `gotchas.md`).
- **Confirmation of the plan's shape, not a change to it.** `pen interactive` is a
  session (globals, one open document, a REPL); the tire-kick note's findings all
  still hold there — pre-layout reads in the creating call, full-rollback batches,
  silent detach on component delete. Our stateless verbs over a locked file, per-node
  revisions, apply-what-you-can batches and name-path addressing remain the
  differentiators. Two ideas do carry over: a `--tasks`-style batch file is our
  `apply -F ops.jsonl` (already planned), and `--enable-preview` — a PNG rewritten
  after every change — is a cheap sibling of `serve` for agents that cannot open a
  browser: `woodcase shot --watch`, parked in `backlog.md`.
