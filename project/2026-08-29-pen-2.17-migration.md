# Migrating to the .pen 2.17 format (Pen.dev)

**Status: DONE, 2026-08-29.** Executed the same day as eleven squash-merged commits (`52f886c` … `5b82ed4` on `main`): 1683 tests green, no MAE moved, React goldens byte-identical, DocC warning-free. The task tree below is closed in `job`; the correction blocks record what execution taught us. The RapidPro follow-on is `../RapidPro/project/2026-08-29-pen-2.17-brief.md`.

## Context

Pencil.dev has been renamed Pen.dev (app: `/Applications/Pen.app`, version 1.2.7). The .pen format has had its first breaking change: the dev-doc schema went from `2.10` (`local/Pen-Schema.js`) to `2.17` (`local/Pen-Schema-v2.js`). Woodcase's models track 2.9/2.10 (`PenDocument.currentFormatVersion == "2.9"`), and nothing dispatches on the version field today.

Every .pen file we hold is 2.8–2.10 (`find . ~/Local/Pen -name '*.pen' | xargs grep -hoE '"version": *"[0-9.]+"' | sort | uniq -c` → 2×2.8, 102×2.9, 10×2.10). One real 2.17 file exists: `~/Desktop/render-strokes-and-paths-pen.pen`, re-saved by Ben on 2026-08-26.

## What changed, 2.10 → 2.17

> **Correction, 2026-08-29 (script/shader session).** Row 10 said rotation should be a no-op; it is, but not because the schema's "top-left corner" wording is a literal description of `PenTransformBuilder`'s pivot. It never was, and changing the pivot to match a literal reading breaks rendering: switching `PenTransformBuilder` from center-pivot to `(0,0)`-pivot raised `PenSnapshotTests`' `render-transforms-and-effects` MAE from 1.12 to 10.77 against its 8.0 threshold (fixture holds an 80×80 rectangle rotated 45°, checked against Pen.app's own rendered PNG). Center pivot is what Pen.app actually draws, and matches `PenRendering.md`'s existing "applied around each node's center point," which was already correct. The schema's "top-left corner" describes the *position anchor*: ``PenLayoutEngine``'s bounding-box expansion for a rotated node keeps the expanded rect's top-left at the node's declared `x`/`y` — the anchor does not move as the node rotates — while the rotation itself still turns the shape around its own center within that expanded box. `PenTransformBuilder` is unchanged; the regression test locking this in is `PenTransformBuilderTests.rotationDoesNotPivotAtTopLeft()`.

The stroke UI screenshot (Position / Weight / Join / Cap) maps 1:1 onto `strokeAlignment / strokeWidth / strokeLinejoin / strokeLinecap`. Alignment is not new to the UI or to us — it is a rename. What the UI and schema *lost* is dash pattern and miter angle, neither of which ever had UI.

## Decisions (settled with Ben, 2026-08-29)

1. **One in-memory model = 2.17.** ~~The current `Pen*` models are moved, verbatim, under a `Legacy` namespace and frozen; new 2.17 models take the real names; a typed translator `PenDocument(legacy:)` normalizes on load.~~ **Revised with Ben, 2026-08-29 (second session):** no frozen model copy. The version gate reads the raw JSON tree; a `PenLegacyMigrator` rewrites 2.8–2.10 keys into 2.17 shape (stroke object → flat keys, `icon_font` → `icon`, rich-text runs → one string, …), emitting a `PenDiagnostic` for every discarded property; then the single 2.17 decoder runs. The `Pen*` models evolve *in place* to 2.17. Rationale: a typed translator needs a full duplicate model tree that only it touches, and it forces the whole port to land before any feature work can parallelize; JSON rewriting lets each feature ship as one green vertical slice. How we know the 2.10→2.17 mapping without the intermediate app versions: the two schemas plus Pen 1.2.7's own re-save of 2.9 files (`Fixtures/v2.17/`) *are* that mapping — the goldens are the oracle. Downstream (layout, renderer, codegen, editing, RapidPro) only ever sees the current model.
2. **Dispatch on `version`, not try/catch.** Parse `major.minor` numerically. `2.8…2.10` → decode `Legacy`, translate. `2.11…2.17` → decode current (we have never seen 2.11–2.16 output; emit a diagnostic below 2.17). Newer minor → decode current + diagnostic. Other major → error. Missing `version` → fall back to try-oldest-first. Rationale: the explicit field makes the chain unnecessary, and the oldest, optional-heavy model would silently accept a 2.17 file and drop `strokeWidth` etc. on the floor.
3. **Encoder always writes 2.17.** `currentFormatVersion = "2.17"`.
4. **Legacy read stays supported** (Ben: "support it if we can"). The translator is also the fixture-migration tool.
5. **Dropped features (dash, miter, rich text) are dropped from the current model**; the translator emits a `PenDiagnostic` when it discards data. ~~converts `line` → `path`~~ **Overturned by the re-save: `line` stays** (table row 2). Ben doesn't want to maintain tests forever for features Pen can't produce. Rich text: confirm first (open question 1).
6. **`script` and `shader`: typed, round-tripped losslessly, not rendered** (script renders nothing; shader fill falls back to nothing/transparent).
7. **Pencil → Pen rename in prose only** (README, DocC, comments). Type names already `Pen*`; the MCP server keeps its `pencil` name.
8. **RapidPro follow-on is the last task**: a planning task that writes `../RapidPro/project/YYYY-MM-DD-pen-2.17-brief.md` with the full change list plus everything learned during execution that affects RP (RapidPro touches `PenStroke` in 10 files, `.stroke` 13, `dashPattern` 5, `iconFont` 4, `LineData` 4; Penumbra touches none).
9. **`viewBox`** — Ben's reading, matching the doc: *Auto* = today's tight-bbox stretch (the source of our path-fidelity fiddliness); *Fixed* = geometry stays in its own coordinate space mapped through the given viewBox, overflow is simply drawn (no clip unless the parent clips). **Confirmed by screenshot in the second session** (see the correction block under open questions): also non-uniform stretch, no aspect preservation. The task keeps its MAE criterion.

> not a decision: `version`, `themes`, `imports` and `variables` were all carried and `fileToken` was not, while

> `FlatStoreSnapshot`, so `materialize()`, `materializeSnapshot()` and `materializeSubtree()` all round-trip it.
> Nothing in the CRDT wire types changed: `fileToken` is document metadata, never synced, exactly like `themes`.
>
> **On-disk formatting.** ``PenParser/encode(_:)`` is unchanged (compact, sorted keys); the new
> ``PenParser/encodeForFile(_:)`` adds `.prettyPrinted`, `.withoutEscapingSlashes` and a trailing newline, and
> rewrites Foundation's `"key" : value` pretty-printing as `"key": value` so the migrated fixtures read like the
> hand-written ones they replace. Sorted keys mean a migrated file's key *order* no longer matches Pen's semantic
> order (`type, id, x, y, …`); that is cosmetic and `GoldenParity` compares parsed documents, not bytes.
