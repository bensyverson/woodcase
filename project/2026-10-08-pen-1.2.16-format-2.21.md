# Pen 1.2.16 (format 2.21): the shader effect (2026-10-08)

Author: Claude (Opus 5.5), for Ben. Findings and a plan; the tasks block at the end is imported into `job`.

## Versions

- Pen.app **1.2.16** was installed 2026-10-08 (`defaults read /Applications/Pen.app/Contents/Info.plist CFBundleShortVersionString`).
- The `pen` CLI **0.3.11** was published to npm the same day (`npm view @pen.dev/cli version`). It is not installed yet: Homebrew's `pen` is still 0.3.10.
- **The bundled skill docs give a clean baseline.** CLI 0.3.10's `dist/out/skills/pen-dev/` is byte-identical to the 1.2.15 schema saved in
  `local/Pen-Schema-2.20.md`, apart from that file's header. CLI 0.3.11's copy is identical to Pen.app 1.2.16's
  (`diff -r`, 0.3.11 fetched with `npm pack @pen.dev/cli@0.3.11`). The diff between the two versions below is therefore the whole
  documented change.

## What changed in the schema (2.20 → 2.21)

1. **`version: "2.21"`.**
2. **A new effect type, `shader`:** `{ type: "shader"; enabled?; url; uniforms?: ShaderUniforms }`. It has no `blendMode` or `opacity`,
   unlike the shader fill.
   - It post-processes the node. The node, its children and its earlier effects are rendered into a `sampler2D` uniform annotated
     `@content`, and the shader's output is drawn *in place of* the node.
   - The shader runs over the node's visual bounds, which include strokes, shadows, blur and unclipped children.
   - Several shader effects chain in list order.
3. **`ShaderUniforms` became a named type.** The shape is unchanged, and the shader fill now refers to it.

`scripts-and-shaders.md` also adds two uniform directives, which apply to shader fills as well:
- `@content`: a fill sees the fills under it, and a stroke sees all fills.
- `@mipmap`.

The docs also say that `@backdrop` mirrors outside the node. No other skill doc changes the format. `execute.md` and `SKILL.md` add one
line each about `Generate` sign-in and Markdown links in answers.

## What Woodcase, RapidPro and Penumbra do today

These results come from probing Homebrew `woodcase` 0.1.3 with a 2.21 file. The file holds a frame with a shadow, an enabled shader
effect, and a disabled one.

- **Read:** the file reads, with the notice `Format version 2.21 is newer than this build's 2.20 … written back as 2.21`
  (`PenFormatVersion.Relation.newerMinor`).
- **Effect decoding:** both shader effects decode as `PenEffect.unknown`.
- **Write:** `woodcase set … kind.width=210` writes the file back as 2.21 with both shader effects intact. Only the key order changes.
- **Render:** the node draws without the shader. This is a sensible fallback, but nothing reports it. A shader *fill* raises a
  `shader-not-drawn` warning (leaf `dYIzYU`); a shader *effect* is silent.
- **Authoring:** a shader effect can't be authored. `.unknown` comes only from a file decode; authoring input with an unknown `type` is
  refused (`PenEffect.swift:24`).
- **RapidPro:** `PenEffect+RenderEffect.swift:41` maps `.unknown` to nothing. That matches CG's behavior, and nothing breaks.
- **Penumbra:** this needs no change today. Its `PropertyFormatter` and canvas effects code switch over `PenEffect`, so a new typed case
  will need a line in each.

**Nothing is broken.** All three consumers read, preserve and render 2.21 files with today's code.

## Behavior: Pen 1.2.16 against 1.2.15

> **Settled 2026-10-08, after `pen login`.** These were open questions in the first draft of this note.

**Method.**
- `scripts/pen-oracle --accept-invalid` (CLI 0.3.11) ran on all 94 fixtures that have committed Pen outputs, at the scale of each
  reference (`--scale 1` for the 34 fixtures exported at 1x, `--settle` for `render-turned-fill`).
- The outputs were compared with the committed references: PNG MAE on premultiplied RGBA, layout rects to 0.01 pt, and re-saves
  leaf by leaf with `fileToken` ignored.
- The committed references came from several Pen versions; all were committed together at `0ce4f51`, so their dates prove nothing.
  Every fixture that differed was therefore re-run through CLI 0.3.10 (1.2.15's engine; `npm install --prefix <scratch>
  @pen.dev/cli@0.3.10`, then put first on `PATH`), and 1.2.16 was compared with that directly.

**Results.**
- **Layout:** identical. All 65 layouts match 1.2.15. One fixture, `layout-fill-container-toplevel` (`topFC` width 200 → 0), and one
  render, `layout-single-child` (220 vs 200 px tall), differ from their committed references, but 1.2.15 produces the same result as
  1.2.16. Those references predate 1.2.15.
- **Rendering:** 332 of 344 same-size PNGs are byte-for-byte identical to their references. Against 1.2.15, only two things differ:
  1. **The ★ glyph.** In `woodcase-app`'s Collection row (`Component-Collection-Row`, MAE 1.38; the three `Home - Collection` boards,
     0.17–0.20), the stars draw narrower and more tightly spaced. The re-save then moves the instance's overridden descendants
     `NODok`, `Yayan`, `mP8DI` and `qo0XP` (the "Stars" text, `$font-primary`) from `x: 277, y: 25.5` to `x: 279/280, y: 26`.
     1.2.15 kept the file's values. This is deterministic across two runs. The likely cause is a change to how Pen measures or falls
     back for symbol glyphs; this is not yet confirmed.
  2. **The `@backdrop` edge.** `render-shader-fills-backdrop` differs by a one-pixel seam at the node's edge (MAE 0.096). This fits
     the newly documented rule that `@backdrop` mirrors outside the node.
- **Re-save:** besides the ★ positions, every re-save differs from 1.2.15 only in `version` (→ `"2.21"`), the per-session
  `fileToken`, and the id Pen mints for an injected descendant in `slot-override-keys`, which is random on every run.
- **Reading old files:** 1.2.16 opens 2.17, 2.19 and 2.20 files and upgrades them to 2.21 with no other rewrite.
- **Known failures:** `banking.pen` fails to export under both versions (`Failed to find a node with id V:akv05`; it is an imports
  fixture). This is not new.

**Consequence for Woodcase.** Nothing breaks. The suite compares against committed references, which still match 1.2.15. If
`woodcase-app`'s references are ever regenerated with 1.2.16, its Collection boards will move by the ★ change. Woodcase's own star
rendering would then need re-checking against the new references.

## Proposed plan

1. **Woodcase:**
   - Bump `PenFormatVersion.current` to 2.21 and add 2.21 to `observedModern`.
   - Save the schema as `local/Pen-Schema-2.21.md` and point AGENTS.md at it.
   - Update the version in the DocC, the CLI help and the README.
   - No migration rule is needed, because 2.21 only adds things.
2. **Woodcase:** a typed `PenEffect.shader(PenShaderEffect)` with a shared `PenShaderUniforms` type that the shader fill also uses. This
   makes shader effects authorable and visible in schema help, and follows the "strongly typed" principle.
   - Every target draws the node unprocessed, which is today's behavior.
   - The `shader-not-drawn` warning and lint cover effects as well as fills.
   - **Breaking for consumers:** RapidPro and Penumbra each need a `case .shader` in their exhaustive switches.
3. **RapidPro and Penumbra:** add those cases, and change the docs' "2.20" to 2.21 where they describe the current format.
4. ~~**Ben:** install the new CLI and run `pen login`.~~ Done 2026-10-08; see *Behavior* above.
