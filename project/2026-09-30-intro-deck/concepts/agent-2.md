# Intro deck concepts: agent 2

## Session

The deck is one terminal session, read top to bottom across nine pages. Each slide is the next screenful, and the prose is the comments between commands. Nothing is typed that the tool would not really print. The idea shapes every slide because every slide is a prompt, a command and its real output, set as a single left-aligned column at a fixed 64-character measure. The ground is a near-black warm charcoal (#141311) with one flat light source: no glow, no scanlines and no window chrome. Text is a warm off-white. One accent, a sodium amber (#E8A33D), marks only the `$` and the thing that changed. JetBrains Mono carries everything at 34px on a 48px line, with IBM Plex Sans for the comment lines at 30px in 60% gray, so the eye separates what a human says from what the machine says. The gap is a single comment on an otherwise empty screen: `# the agent wrote 4,000 lines of UI. it has never seen any of them.` The loop is three commands stacked on one page: `tree` with the real banking output, `set … --rev 7cf8d84e`, then `shot`. The `shot` output is the one place pixels appear, a 402×874 phone render inset where the output would print. The JavaScript slide is a heredoc of a twelve-line `woodcase js` script that measures, throws, and prints `nothing written`. The outlets slide is `woodcase generate swiftui` and `generate react` printing their file trees side by side. The slide that breaks the pattern is the reveal: `woodcase activity intro-deck.pen` fills the screen edge to edge in 18px type, hundreds of real entries too small to read individually, with the amber cursor waiting on the last line. Before reading a word, the reader sees a dark page with one column of mono text and a single warm dot of color: *this is a terminal*.

## Verbs

Each slide is one word set so large that it is the composition, and the explanation is a small caption in a corner. The idea is the grammar: the deck is the CLI's verbs, in the order an agent uses them. `tree`, `set`, `shot`, `js`, `generate`, `undo`, `brew`. Every slide has the same structure (verb, one sentence, one small artifact), so the rhythm itself teaches that the tool is a small language. The ground is paper white (#F4F2EE) with ink-black type. Each verb gets a single flat field of color filling the bottom third: signal red for `set`, cobalt for `js`, and so on, a seven-color set drawn from print inks rather than a UI palette. Archivo Black sets the verb at 520px, tracked −4%, cropped by the bottom edge of the page so the descenders fall off. Space Mono at 28px handles the caption and the artifact. The gap is the one slide with no verb, only a lowercase `?` at the same scale, floating where a verb would be. The loop takes three consecutive slides, TREE, SET and SHOT, each with its fragment of real output. JavaScript is `js` set in the same weight, with `throw` in the caption as the only word in color. The outlets are GENERATE with a stack of small labels (CGContext · PNG · PDF · React · SwiftUI) in the color band like a stamp. The reveal breaks the pattern: the verb field is replaced by the activity log, one line per write that made this deck, and each verb from earlier slides is highlighted where it occurs in the log. Before reading, the reader sees an enormous black word cropped by a band of color, like a poster.

## Wireframe

Every slide shows its own layout. Each element on each page is drawn with its settled rect in a hairline and labeled, in small type at its top-left corner, with its node id and `x,y w×h`, exactly as `tree` would report it. The idea is that the reader looks at a design the way an agent does, and the annotation is the design, not a decoration. The ground is a cool pale gray (#EEF0F2) and the content is black. The annotation layer is a single cyan (#00A3C4) at 1px strokes, with dimension ticks. The light is flat, with no shadows except on the one rendered `shot`. Inter Tight at 88px/600 sets the headlines; Inter at 32px sets the body; IBM Plex Mono at 15px sets the annotations. The gap slide shows a headline with *no* annotation at all: a design the agent cannot see, with a single cyan label floating off to the side reading `?`. From the loop slide on, the annotations appear. The loop slide shows the banking home screen as nothing but labeled cyan rects (the tree), then the same screen rendered (the shot), with one rect changed between them. JavaScript shows a small script whose `measure` call draws a cyan dimension line on the element it measured. The outlets slide shows one card with its rects, and three arrows out to the same card as a SwiftUI snippet, a React snippet and a PDF page. The reveal breaks the pattern by inverting the layers: the content drops to 10% opacity and the annotations go to full black, so the reader sees that every label on every previous slide was real `tree` output. Before a word, the reader sees fine cyan boxes around everything, which reads as *a design tool's view*.

## Table

Every slide is laid out on the columns of `tree` output: `type`, `name`, `rect`, `clip`, `id`, then a wide last column for content. The idea is that the deck's grid is the tool's table. Headlines sit in the content column, and the other columns carry real metadata for the slide's own nodes, so the grid is honest rather than borrowed. The ground is off-white (#F7F6F2). Rules are 1px warm gray, with black type and one red (#D23A1E) for row highlights. The light is flat print. IBM Plex Mono at 22px sets the column cells in gray; IBM Plex Sans Condensed at 96px/600 sets the headline, which runs in the content column and breaks the row height. That tension, a giant row among small ones, is the typographic move on every page. The header line `rev 7cf8d84e7b6b9b23  n rows` sits top-left as a running head, with the rev different on every page. The gap is a table with one row: `text  claim  …  Agents can write the code but can't see the design`, followed by a red empty row labeled `frame  ?`. The loop slide is the only one that uses the real banking output verbatim, with the `set` row highlighted in red after the change and a small `shot` thumbnail in the content cell. JavaScript shows rows being inserted: new rows ghosted at 40% until a final `commit` row makes them solid. The outlets slide's rows are output types (`png`, `pdf`, `react`, `swiftui`) with the path each produced. The pattern breaks at the install slide, where there is no table: `brew install bensyverson/tap/woodcase` alone, centered, the only centered element in the deck. Before reading, the reader sees a ledger with one giant line in it.

## Margin

The activity log is the spine of the deck. A narrow left column (360px) on every slide lists the real log entries that built *that* slide: timestamp, agent name from `--as`, verb and target. It accumulates, so slide 1's column is short and by slide 7 it is dense. The right side holds the argument in plain, generous type. The idea: the reader is watching the deck being made the whole time, and the reveal only names what they have already been reading. The ground is a warm light gray (#E9E6E0) for the margin and pure white for the page, split by a vertical hairline. The light is flat. The accent is one deep green (#1F5C45) for the author name in the log. Newsreader at 72px sets the headlines, as a serif against the machine margin, with Newsreader Text at 34px for the body and Geist Mono at 14px for the log. The gap is the white side almost empty: one sentence, with the margin holding three entries. The loop shows the `tree` excerpt as a pull quote with a `shot` beside it, and the margin shows the `set` entries that produced that very `shot`. JavaScript shows a script, and in the margin a single log entry marked `js (1 transaction, 23 writes)` bracketing the rows it wrote. The outlets slide is a clean diagram: one engine box, five outlet labels. The reveal breaks the pattern: the margin widens to take the whole page, and the argument shrinks to a single line in the old margin's position. Before reading, the reader sees a two-column page like an annotated manuscript, with a dense gray column of small entries on the left.

## Engineering drawing

Every slide is a sheet from an engineering drawing set. Each has a title block in the bottom right with sheet number, revision (the real rev token), `DRAWN BY` (the agent's `--as` name) and `SCALE 1:1`. Dimension lines with arrowheads measure the key elements. The idea: Woodcase treats design as measured, versioned and attributed, and the drawing-set convention already means exactly that. The ground is a drafting white (#FAFAF7) with a 1px black border inset 40px. Linework is black. One blueprint blue (#1B4F9C) is used for dimensions and callout balloons. The light is flat. IBM Plex Sans Condensed sets everything in caps: 64px headlines tracked +2%, 26px notes, and 14px title-block cells. IBM Plex Mono sets the values. The gap is sheet 1: a phone outline with every dimension line present and every value reading `?`. The loop is three detail views, labeled A, B and C in balloons, tree, set and shot, with the revision block showing rev A → rev B. JavaScript is a "general notes" block with the script as numbered notes and a callout reading `NO WRITE UNLESS SCRIPT ENDS CLEANLY`. The outlets slide is an exploded view with a central assembly (the library) and leader lines to the parts: CGContext, PNG, PDF, React, SwiftUI. The reveal breaks the pattern: the revision table in the title block grows up the whole right side of the sheet, listing every revision of this deck, and the drawing shrinks to a key plan. Before reading, the reader sees a technical drawing: a border, a title block and blue dimension arrows.

## Resolution

The deck gains sight as it goes. The first slides are drawn only as what an agent can read, text and numbers, and each slide renders a little more until the last are full-color, finished pixels. The idea is the product's promise played out over time: from blind, to text-described (`tree`), to seen (`shot`). The ground starts pure black and brightens slide by slide through grays to a clean white by the outlets slide. Color is absent until the loop's `shot`, where the banking app appears as the deck's first color; after that, color stays. Type moves with it: slides 1–2 are all Martian Mono at 36px, gray on black. From the loop on, Instrument Sans enters for headlines at 84px/600, and the mono recedes to a supporting role. The gap is a black page with a line of gray text, `frame  banking-home  0,0 402×874`, and nothing else: a design that exists only as coordinates. The loop is the turn: the left half is the same screen as `tree` text, the right half is the same screen as `shot` pixels, split by a hard vertical edge. JavaScript sits on mid-gray, a script at left and a shaded region at right showing the before/after layout it measured. The outlets are on white: one small card rendered five ways in a row. The reveal breaks the arc by going back to black: the whole deck's activity log as text, the deck returning to how its author saw it. Before reading, the reader sees darkness with one line of faint type, and on flipping, a page that gets lighter.

## Title cards

Woodcase started as agentic title design inside a video editor, so the deck is a film's title sequence. Each slide is a title card in a letterboxed 2.39:1 field with black bars top and bottom, one line of type or one image per card, and the reveal is the end credits. The idea shapes every slide because each gets exactly one statement, timed like a card. The ground is black bars around a deep ink field (#0E1014). A single soft radial gradient sits behind the type as a stage light, and the only accent is a warm tungsten (#F2C58A). Fraunces at 110px/300 sets the italic statement cards; Space Grotesk at 20px caps, tracked +20%, sets the small "chapter" labels above them. Commands are set in Space Grotesk too, never mono, so they read as dialogue. The gap is a card with one line: *The agent wrote the app. It has never seen it.* The loop is three quick cards with a shared composition: `tree`, `set`, `shot`, each a single word with its one-line gloss, and the third card holds a rendered shot in the letterbox. JavaScript is a card of the script set as a poem, line breaks where the code breaks, with `throw` in tungsten. The outlets card is a centered list in the manner of a studio's distribution logos, CGContext · PNG · PDF · React · SwiftUI, set small and evenly spaced. The reveal breaks the pattern: the letterbox opens to full frame for the first time, and the end credits roll as a two-column list, with the job on the left (the verb) and the name on the right (the agent from `--as`), every write that made the deck. Before reading, the reader sees black cinema bars and one lit line of type.

## Flipbook

The whole deck is one frame being edited. Every slide is the *same* layout at a later revision, one `set` (or one `js`) away from the previous page. The command that made the change is printed at the top, and the changed node is outlined. The idea is the loop made physical: flipping the PDF is iterating, and the reader watches the deck converge. The ground is a steady warm white (#F5F3EF) throughout, because it never changes. Color arrives only when a `set` adds it: the first `fill` command introduces a single vermilion (#E4572E) that stays for the rest. Type is also subject to editing. The first slide is the default Inter at 32px; one slide's `set … fontFamily "Bricolage Grotesque"` changes the headline face mid-deck, in front of the reader. The running head is always `rev <token>  set <node> <prop> <value>` in Geist Mono at 18px. The gap is revision 1: an unstyled frame with the sentence in default type, visibly unfinished. The loop is the next three revisions, where each slide is literally one iteration and the `tree` row for the changed node appears as a strip at the bottom. The JavaScript slide is the one where many things change at once, with the running head showing a `js` command and a count of 23 writes in 1 transaction, outlines around every changed node. The outlets slide is the same frame beside its generated SwiftUI source. The pattern breaks at the reveal: instead of another revision, the page shows every previous revision as small thumbnails in a grid with their rev tokens: the flipbook seen all at once. Before reading, the reader sees a plain, almost default slide with one thing outlined, and senses something is about to change.

## Woodcut

The name is taken at its word. Every slide is a relief print: flat, two-ink and cut. Letterforms and shapes have the chunky, slightly irregular edges of a carved block, drawn as paths, with parallel gouge lines as hatching instead of gradients. The idea: design carved by a tool, not painted, and each slide is one pull of the press. The ground is a warm, unbleached paper (#EDE4D3). Ink is a dense black-brown (#1D1812), and a second block prints a single vermilion (#C7361F), misregistered by 3px on purpose. There is no light at all, only ink or no ink. Rye is too costume-like; instead, Alfa Slab One at 180px sets the headlines, cut into blocks with a fixed-rotation hatch fill behind them. Courier Prime at 30px sets the commands, as if set in metal type beneath the print. The gap is a block print of an eye with its pupil carved away, a hole, and one line beneath. The loop is a three-panel print, like a triptych cut from one block: a hand-cut rendering of the tree as stacked bars, a vermilion stroke marking the `set`, and a finished card as the `shot`. JavaScript is the one slide printed in vermilion only: the script carved as a column of text, with `throw` cut deeper. The outlets slide is one central block with five prints pulled from it, each slightly offset, labeled CGContext, PNG, PDF, React, SwiftUI. The reveal breaks the pattern by stripping the craft: plain black mono on paper, the activity log with no carving, showing that every "cut" was a `set`. Before reading, the reader sees a heavy two-color print on warm paper, which is the last thing they expect from a developer tool.
