# Concepts: agent 1

## Session

The deck is one terminal session, scrolled forward a screen at a time: every slide is the next page of a single shell, and the story is told in commands and their real output, with the prose living only in `#` comments. Ground is a near-black warm charcoal (#141311) with a faint 2% radial glow from upper left, as if lit by the screen itself; text is a bone off-white (#E8E4DA), comments in a dimmed 45% version of it, and one signal color, a sodium amber (#F2A33A), reserved for the prompt `$` and for whatever the reader must not miss. Type is JetBrains Mono throughout, 34 px for output and 56 px for the one command per slide, tight 1.3 leading, left-aligned on a 12-column grid with a 160 px left margin, never centered. The gap is a single comment line, `# the agent wrote 4,000 lines of UI. it has never seen any of them.`, followed by an empty prompt with a blinking-block cursor drawn as an amber rectangle. The loop is the real `tree banking.pen banking-home/header` output from the brief at full size, then one `set` line and its `rev` change, then a `shot` whose output is the header itself rendered inline beneath it, the only pixels on any slide so far. JavaScript is a ten-line heredoc into `woodcase js` with a `throw` on line eight, and the output is `rolled back · nothing written`. The engine's outlets are one command with its output forked four ways: `render --format pdf`, `generate react`, `generate swiftui`, and a CGContext line, each ending in a file path. The pattern breaks at the reveal: the terminal "clears" and the slide is `woodcase activity intro-deck.pen` with the actual log that built this deck filling the page edge to edge in 20 px type, too dense to read, the point being its density. Install is a lone prompt with the brew line in amber. Before reading, the reader sees a dark screen with one bright line in it: it looks like their own work.

## One Line

Each slide carries exactly one sentence, set enormous, and nothing else unless the sentence cannot stand without it; the idea is that the deck behaves the way the CLI does, one thing at a time, and it earns its restraint by letting only two slides show evidence. Ground is paper white (#FAFAF7) under flat, even light; type is ink black (#111); a single slate-green (#2F5D50) marks one word per slide, the word the reader would underline. The face is Inter Tight at 132 px, weight 600, tracking -2%, set flush left in a text block no wider than 1400 px and placed on the lower third so the upper two thirds are empty air. The gap: "Agents can write the interface. They cannot see it." The loop: "Command. View. Iterate." with the three words stacked and nothing else. JavaScript: "Read, decide, write, measure, or write nothing." The outlets: "One engine. Any context, any file, any framework." The pattern breaks twice: the loop is followed by a single evidence slide where the sentence shrinks to a 28 px caption and the `tree` output fills the page in IBM Plex Mono, and the reveal replaces the sentence with the deck's own activity log at caption size under a one-line headline, "Every slide here was a command." Install is the brew line alone, in Plex Mono at the headline's size. Before reading, the reader sees a white page with a dark block of type sitting low, and a lot of nothing: confidence.

## Swiss Index

A strict international-style editorial system: a visible 12-column, 8-row grid on every slide, numbered beats in a left rail, and each slide treated as a spread in a technical monograph, so the structure of the deck itself becomes an argument about structure. Ground is a cool light gray (#EDEDEA); type is black; the sole color is a signal red (#E0321E) used for rule lines, the beat numeral and at most one filled rectangle per slide. Type is Space Grotesk for display (180 px numerals, 64 px headings, tight) and IBM Plex Mono at 22 px for all code and captions, running in two columns with a hairline rule between. The left rail carries a huge red numeral per beat (01–08) that sits half off the top edge. The gap is a red rectangle occupying six columns, empty, labeled "what the agent sees", beside a black-outlined rectangle of the same size holding a small rendered phone screen from `banking.pen`, labeled "what you see". The loop is three columns — `tree`, `set`, `shot` — each a stack of real output cropped to the grid, joined by a red rule that bends back from the third to the first. JavaScript is a single code block on eight columns with the one `throw` line highlighted by a red bar in the gutter. The outlets are a four-row table: CGContext, PNG, PDF, React, SwiftUI, each row one line of fact and one red square. The reveal breaks the grid: the rules disappear and the deck's own `tree --depth 1` output is set at 40 px across the whole page, showing these slides as nine 1920×1080 frames with their ids. Before reading, the reader sees order — a red number, a ruled grid — and assumes rigor.

## X-Ray

Every slide shows its own skeleton: each is drawn twice at once, the finished composition in full color and, overlaid in thin cyan hairlines, the rect of every node with its name and id in the corner exactly as `tree` would print it, so the reader learns what `tree` means by looking at the deck rather than being told. Ground is a deep ink blue (#0E1A2B) with a flat, slightly cool light; content is white and a pale warm gray; the overlay is a single cyan (#5FD4E8) at 1 px stroke with 12 px labels, and dimensions ride along each rect as engineering-drawing callouts (`402×72`). Display is Instrument Serif at 120 px, italic for emphasis, a deliberate contrast with the machine hairlines; labels and code are Geist Mono. The gap: a phone screen rendered from `banking.pen`, fully opaque, with no overlay at all and the line "This is all an agent gets from a screenshot." The loop: the same phone, now with the overlay switched on, every node boxed and labeled, and the `tree` table printed beside it with rows linked to their boxes by leader lines; the `set` is one box whose label turns amber. JavaScript: a single node's box drawn in three positions like a motion study, the third struck through in red, captioned "measured, then refused". Outlets: one component box whose leader lines fan out to four destination labels, PDF, PNG, React, SwiftUI. The reveal breaks the pattern by switching the overlay off the content entirely and onto the deck: a small-multiples map of all slides as boxes with their real ids, and beside it the activity log lines that created each one. Before reading, the reader sees a technical drawing — structure glowing through a surface.

## Main Titles

The deck is a title sequence, because the first real use of Woodcase was agentic title design inside a video editor: each slide is a film title card, and the deck plays as an opening sequence and closes as end credits. Ground is true black with a very soft vignette; type is a warm white, with a single tungsten-orange (#E8894A) glow used as an outer shadow behind the one key word per card, like light blooming off a projected title; a thin timecode sits in the lower-right corner of every card (`00:00:04:12`) in a dim gray and advances through the deck. Display is Cormorant Garamond at 150 px, generously letterspaced in capitals for the card titles, with Space Mono at 22 px for the timecode and any code. The gap: "AGENTS CAN WRITE THE PICTURE. THEY CANNOT SEE IT." centered, like an epigraph. The loop: three consecutive-feeling cards merged into one slide as a three-panel strip of film frames, each frame holding one command and its tiny result. JavaScript: a card with a slate (the clapperboard, drawn as rectangles and rotated stripes) marked "TAKE 2 — TAKE 1 NEVER PRINTED". Outlets: a title rendered four ways side by side, as the same card for screen, print, web and app. The pattern breaks at the reveal: end credits, left-aligned in two columns, crediting each `--as` writer from the deck's own activity log with the verb they ran, like cast and crew, with the brew line as the final card after the credits. Before reading, the reader sees cinema: a black field and one warm line of light.

## Diptych

Every slide is split exactly down the middle into the same two halves: on the left, what a human sees — pixels; on the right, what an agent sees — text; the entire argument is carried by the fact that the right half is always enough. Ground is split too: left half a warm off-white (#F4F1EA), right half graphite (#1C1C1E), a hard vertical seam with no gutter. Color on the left is whatever the rendered design brings; the right is monochrome white-on-graphite with a single chartreuse (#C6F432) for revision tokens and ids. Left captions are in Fraunces at 48 px; the right half is all Commit Mono at 26 px. The gap: left is the rendered banking home screen; right is empty except `?` — the agent's half is blank. The loop: left the same screen, right its real `tree` output, rows aligned by baseline to the element they describe across the seam. JavaScript: left shows the header after a change, right shows the script, and the chartreuse revision token is the same on both sides because nothing was written. Outlets: the seam multiplies — the right half splits into four narrow columns of React, SwiftUI, PDF operator stream and PNG byte header, all generated from the one pixel image on the left. The reveal breaks the pattern: the seam goes away and the whole slide is the right half — graphite, text, the deck's own activity log — because the reader has now looked at nine slides whose left halves were made from the right. Before reading, the reader sees a hard black-and-white split and understands, wordlessly, "two views of one thing."

## Type Case

Take the name literally: a woodcase is a printer's type case, the drawered wooden tray of sorted letters, and the deck is designed as a letterpress proof set — each slide a proof pulled from a case, where parts are sorted, addressable and composed by hand into a form. Ground is an uncoated kraft-cream (#EFE6D3) with a subtle mesh-gradient mottling to suggest ink absorption; ink is a dense black and a vermilion (#D6402B), printed with a slight 1–2 px misregistration offset between the two colors. Display is Alfa Slab One at 200 px, set like wood type with visible, uneven tracking; text is Courier Prime at 28 px, as if typewritten onto the proof. The case itself is the recurring image: a grid of rectangular compartments of unequal sizes, each holding a label — a verb, a node id, a format. The gap: an empty case, every compartment blank, captioned "the agent has the letters but no case." The loop: three compartments pulled forward and printed large: TREE, SET, SHOT, with their output typewritten underneath. JavaScript: a composed form — lines of type locked in a chase drawn as a heavy black frame — and the caption "locked up whole or not at all." Outlets: one form pulled as four proofs laid overlapping at slight rotations, each stamped PDF, PNG, REACT, SWIFTUI in vermilion. The reveal breaks the mood: a clean white page, no texture, with the activity log printed in Courier Prime as the compositor's job ticket for this deck. Before reading, the reader sees a warm, tactile, obviously crafted object — something made, not generated.

## One Canvas

The deck is a single enormous design, and each slide is a camera position on it: a 1920×1080 frame that crops a region of one continuous canvas, so moving through the slides feels like panning and zooming across a single board where the banking app, the terminal, the code outputs and the deck itself all sit side by side. Ground is a mid-neutral canvas gray (#D9D8D4) with a 24 px dot grid; artboards on it are white with soft 30 px outer shadows; the only accent is an electric blue (#2E5BFF) used for selection outlines and for the one label per slide. Type is Manrope, 72 px for the one caption per slide, placed in a floating white label that sits on the canvas like a sticky annotation, and JetBrains Mono for anything that is code. The gap: a tight crop of the phone screen, far zoomed in, blurred at the edges with a layer blur, captioned "an agent is looking through a keyhole." The loop: zoom out a step; the phone is now an artboard with a blue selection box on the header and, beside it on the canvas, a terminal artboard holding the `tree` output. JavaScript: pan right to a code artboard with a blue arrow connecting it to the node it moved. Outlets: pan further to four smaller artboards in a row — PDF page, PNG, React file, SwiftUI file — each connected to the phone by a thin blue line. The reveal breaks the pattern by pulling all the way out: the whole canvas visible at once, every earlier slide's crop drawn as a thin blue rectangle on it, and in the corner the activity log that placed every object. Before reading, the reader sees a workspace — a design tool's canvas — and only on the reveal realizes it was one file.

## Ledger

The activity log is the spine of the whole deck, not just its reveal: every slide carries, in a fixed band along its bottom 200 px, the actual log lines that built that slide, timestamped and attributed, so the reveal is prepared from the first page and lands as a turn of the lens rather than a surprise. Ground is a pale ledger green-gray (#E6EBE4) above, and the band is a darker bottle green (#1F3A30) with pale text, divided from the page by a double rule like an accounting book; the page area is flat and quiet, the band slightly denser and brighter. Headlines are in Newsreader at 96 px, editorial and calm; the band is IBM Plex Mono at 18 px, time, `--as`, verb, path, in fixed columns. Above the band each slide has a headline and at most one object. The gap: the headline "Agents ship interfaces blind" and an empty band — no log lines, because nothing can be written that the agent can see. The loop: three log lines in the band (`tree`, `set`, `shot`) and, above, the three results they produced placed in a row. JavaScript: one band line, `js`, with a count of 14 nodes touched in one transaction, and above it a single struck-through second line that never reached the log. Outlets: the band lists `render`, `generate react`, `generate swiftui`, and the page above shows their four files as flat cards. The reveal breaks the pattern: the band rises and fills the page — the log of the entire deck, every line, with the earlier slides' lines highlighted where they appeared. Before reading, the reader sees an account book: a quiet page over a dense, dark strip of records.

## Revisions

The deck is one artifact improved nine times: every slide is the same 1920×1080 composition — a title card for Woodcase — at a successive revision, beginning broken (overflowing text, misaligned, clipped, as `tree` would flag with `⚠ clipped`) and ending finished on the install slide, so the reader watches the loop run instead of hearing it described. Ground starts as raw white with default black Helvetica-like system type and harsh red lint warnings, and converges revision by revision toward the final palette: a deep aubergine ground (#2A1B2E) with lilac (#C9B6E4) and one saffron (#F5B83D) accent. Final typefaces are Syne at 160 px for the wordmark and Geist Mono for all annotations; the earlier revisions intentionally use the renderer's fallback so the typography itself arrives as an edit. Each slide shows the card large, with a margin strip on the right in Geist Mono listing the rev token, the one command that produced this revision, and what `tree` said before it. The gap is revision 0: an agent's unseen first draft, text overflowing its frame, and the caption "it compiled." The loop is revisions 1–3 on one slide as three stacked thumbnails, each with its `tree` warning and its `set`. JavaScript is revision 4: one script that measured the title, found it clipping, and threw — the card is unchanged and the rev token is the same. Outlets is revision 7: the finished card shown as PDF, PNG and as a SwiftUI preview frame. The reveal breaks the pattern: every revision side by side in a contact sheet with the real rev tokens from this deck's own history. Before reading, the reader sees something visibly wrong — a broken title card — and keeps going to see it fixed.
