# scripts/

Analysis and fixture tooling, run by hand or from the pre-commit hook. Check here before
writing a new one-off script — most needs are already covered.

| Script | What it does |
| --- | --- |
| `install` | Builds `woodcase` in release and installs it Homebrew-style: the binary and `Woodcase_Woodcase.bundle` in `<prefix>/libexec/woodcase/`, a relative symlink in `<prefix>/bin/` (default prefix `~/.local`). Re-running upgrades in place, staging then moving so no signed binary is overwritten; `--uninstall` removes it. Says so when the install is not on `$PATH`, or is shadowed by another `woodcase`. Needs the sandbox disabled. |
| `pen-oracle` | Runs Pen's own engine headless (`pen interactive`) on a `.pen` fixture and writes what our tests compare against: layout JSON (Pen's *first* layout after load — see `pen-settle`; `--settle` relays the document out first, so the layout and the PNGs are Pen's settled ones), PNG export(s), and Pen's own canonical re-save. A fixture *generator*, run by hand — the test suite never calls `pen` (see [project/2026-08-29-pen-cli.md](../project/2026-08-29-pen-cli.md)). Needs the `pen` CLI, logged in, and the Bash sandbox disabled. |
| `gen-kit-fixture` | Writes `Tests/WoodcaseTests/Fixtures/kit.lib.pen`, the original component library `banking.pen` imports: 89 reusable components, 25 tokens over three theme axes (`scheme` × `tint` × `contrast`), ref chains, slash-path overrides, per-side strokes and disabled children. Ids are hashed from stable keys, so the output is a pure function of the script; `--check` exits 1 when the file on disk differs, `--report` prints the coverage counts, `--ids <key>…` prints the id for a node key (tests name them), and `--sync-host <file>` copies the library's tokens into a host that keeps its own copy (`banking.pen`). Standard library only; runs sandboxed. |
| `pen-settle` | Runs Pen's engine headless on a `.pen` file and writes both its first layout after load (`<name>.first.layout.json`) and its settled one (`<name>.settled.layout.json`), after nudging every frame's `gap` and back for `--rounds` rounds (default 3); prints the rects that move and exits 1 if the last two rounds disagree. Pen fits widths before heights, so on load a turned child whose height is unresolved measures at height 0; `pen-oracle` captures that pass. Compare either file with `layout-diff`. Needs the `pen` CLI, logged in, and the Bash sandbox disabled. Standard library only. |
| `gen-paint-geometry-fixtures` | Writes `render-gradient-geometry.pen` (linear, angular and radial gradients at several rotations, centres and sizes on square, wide and tall boxes), `render-per-side-strokes.pen` (per-side stroke widths under each `strokeAlignment`, square and rounded) and `render-stroke-fills.pen` with its `images/uv-map.png` (gradient and image paints on strokes of every alignment and shape) into `Tests/WoodcaseTests/Fixtures/`; their Pen references come from `pen-oracle` (the header has the three commands). `--check` exits 1 when a fixture differs. See [project/2026-09-26-gradient-geometry-and-per-side-strokes.md](../project/2026-09-26-gradient-geometry-and-per-side-strokes.md). Standard library only; runs sandboxed. |
| `gen-free-groups-fixture` | Writes `Tests/WoodcaseTests/Fixtures/render-free-groups.pen`: one board per case of a group whose children reach past its anchor — placed freely and in a flex flow, turned, flipped, nested, blurred, shadowed, and at the root. Its Pen references come from `pen-oracle` (the header has the command); `PenFreeGroupTests` pins Woodcase's layout and CG render against them. Standard library only; runs sandboxed. |
| `gen-geometry-probe` | Writes the geometry-model probe to a path you give — `Tests/WoodcaseTests/Fixtures/geometry-probe.pen` is its output, with Pen's 2x exports of the `free`, `groups` and `x1`–`x4` boards beside it (`PenPaintedExtentProbeTests`): thick inner/centre/outer and per-side strokes, shadows and blurs on flex, group and free children, turned, flipped and both, with `layoutIncludeStroke`, turned `fill_container` children, text and icons, and top-level nodes whose Pen export is bounded by their painted extent. Run `pen-oracle` on it and compare with `layout-diff`. Reproduces [project/2026-09-28-geometry-model.md](../project/2026-09-28-geometry-model.md). Standard library only; runs sandboxed. |
| `pen-font-audit` | For every family in Pen's bundled Google font table (1,899 in Pen 2026-09), compares the file Pen draws — static or variable, its axes, its fonts.gstatic.com version, the styles it offers — with the file Woodcase's Google font resolver picks from google/fonts, using the library's own `GoogleFontMetadata` parsing and `entry(weight:style:)`, compiled in. One tab-separated row per family on stdout, the agreement and disagreement counts on stderr. Reads a local google/fonts checkout of METADATA.pb files only (`local/google-fonts`, made on first use; `--update` pulls it); downloads no font. See [project/2026-09-28-pen-font-faces.md](../project/2026-09-28-pen-font-faces.md). Needs the sandbox disabled. |
| `pen-font-table.py` | Prints Pen's bundled Google font table, read from `app.asar`, as JSON: each family's styles with their gstatic URL, weight, italic flag and variation axes. `pen-font-audit` reads it. Standard library only; runs sandboxed. |
| `font-advance-diff.py` | Compares two builds of one face — google/fonts' file and fonts.gstatic.com's, say: their version strings, and the advance of every codepoint both map at each named weight. Differing advances move layout; differing outlines only move pixels. fontTools. |
| `plex-face-widths.swift` | Sets every auto-width IBM Plex Sans text in the `layout-text-*` fixtures in a variable face and, optionally, the old static cuts, beside the width Pen's layout gave it. `swift scripts/plex-face-widths.swift <variable.ttf> [<static-dir>]`; needs the sandbox disabled. See [project/2026-09-28-pen-font-faces.md](../project/2026-09-28-pen-font-faces.md). |
| `gen-static-test-family.py` | Writes "Woodcase Static Sans" into `Tests/WoodcaseTests/Fonts/StaticSans/`: Inter cut at 400, 500, 600 and 700, subset to ASCII and renamed (Inter's OFL reserves no name), the static family `PenFaceMatchingTests` and `SwiftUIFaceMatchingTemplateTests` resolve weights in. `--check` exits 1 when a committed cut differs. fontTools. |
| `mae-log-diff.py` | Lists every MAE figure that moved between two `swift test` logs (run without `--quiet`), pairing lines by their text with the figures blanked — the before/after of a change that moves many gates at once. Standard library only; runs sandboxed. |
| `layout-diff` | Compares a `pen-oracle` `<name>.layout.json` with `woodcase tree --json` id by id and prints every rect that differs by more than 0.01 pt (`--all` prints all). Standard library only; runs sandboxed. |
| `gen-react-fx-fixtures` | Writes the probes of React's inner shadows and painted lines into `Tests/WoodcaseTests/Fixtures/`: `render-inner-shadow-shapes.pen` (inner shadows on polygons, paths — stroked, viewBox-stretched, two shadows, blended, gradient-filled — a donut, an arc, and Lucide and Material Symbols icons) and `render-painted-lines.pen` (gradient and stacked strokes on full-width and fixed flat lines, with the ramps a zero-height box collapses on a board of their own). Their Pen references come from `pen-oracle --scale 2`; `ReactRenderWebViewTests` gates them. Standard library only; runs sandboxed. |
| `gen-react-gap-fixtures` | Writes the four probes of React's effect and stroke gaps into `Tests/WoodcaseTests/Fixtures/`: `render-angular-shapes.pen` (angular gradient fills and strokes on polygons, paths, a line, a donut and an arc), `render-inner-sides.pen` (children of frames with inner per-side strokes: Pen moves none), `render-unstroked-lines.pen` (lines with no stroke paint, on grey) and `render-stroke-bands.pen` (strokes on 0×0 and sized boxes with the outer shadows they cast). Their Pen references come from `pen-oracle --scale 2` (the header has the commands); `ReactRenderWebViewTests` gates them. Standard library only; runs sandboxed. |
| `gen-turned-fill-fixture` | Writes `Tests/WoodcaseTests/Fixtures/render-turned-fill.pen`: one board per turned `fill_container` flex child — main axis, cross axis and both, in rows and columns, at 30°, 60° and 90°, with blue siblings that show its slot, and no text. Then `scripts/pen-oracle <fixture> --scale 2 --settle` (sandbox off) writes Pen's settled layout and exports (`PenTurnedFillRenderTests`, the React and SwiftUI render gates). Standard library only; runs sandboxed. |
| `gen-stroke-shadows-fixture` | Writes `Tests/WoodcaseTests/Fixtures/render-stroke-shadows.pen`: one board per case of a stroked node casting an outer shadow — outside, centred and inside strokes, rounded, translucent, per side, a frame with a child, an ellipse, a polygon, a path and two lines — and an inside stroke over an inner shadow. Its Pen references come from `pen-oracle --scale 2` (the header has the command); `PenStrokeShadowSnapshotTests` pins the CG render and `SwiftUIRenderTests` the SwiftUI one against them. Standard library only; runs sandboxed. |
| `pen-provenance-check` | Reads Pen.app's `app.asar` directly and compares every repo `.pen` (tracked and new) with the documents Pen bundles, by ids, names, texts and variables. Fails on a distinctive overlap (a shared id, 5+ shared variables, a shared phrase of 3+ words) that is not in its `KNOWN` table of ruled-on cases; `--all` also lists generic overlaps ("Settings", "Label"). See [project/2026-09-26-fixture-provenance-audit.md](../project/2026-09-26-fixture-provenance-audit.md). Needs the sandbox disabled. |
| `pen-validate` | Validates `.pen` files against Pen's own validator, as a black box, by round-tripping each through the headless `pen` CLI (`pen interactive --in/--out`, a plain `save()`). Prints `PASS`/`FAIL` per file with the validator's own messages. A FAIL covers a load failure *and* a non-empty validator error list alike — Pen's engine can log "Document is not valid" and still load and save the file, silently dropping whatever it flagged, so a clean exit and a written output are not proof the validator was happy. `--allow-unknowns` PASSes a file whose every reported violation is an unrecognized property or an unrecognized enum/node-type value — the shape `Tests/WoodcaseTests/Fixtures/parser-unknown-properties.pen` and `preserved-extras.pen` are built to produce on purpose; any other violation in the same file still FAILs even with the flag. On a PASS, also diffs the re-saved JSON against the input — ignoring the per-session `fileToken` — so a silent rewrite (a migration, a dropped key, a materialized default) shows up as data instead of going unnoticed. Hand-run only, never called by the suite, and vendors nothing from Pen — it only drives the installed CLI and diffs JSON already in the caller's checkout. See [project/2026-09-26-pen-1.2.14-compatibility.md](../project/2026-09-26-pen-1.2.14-compatibility.md) §"Which engine produced which evidence" and Appendix A2. Needs the `pen` CLI, logged in, and the sandbox disabled. |
| `deep-pen` | Prints a `.pen` document nested deeper than any fixture — `frames <depth>` (one plain frame tree) or `instances <depth> [--frames N]` (components each placing the one before) — the documents the stack-depth tests generate, for re-running `woodcase tree` on a built binary. See [project/2026-09-26-debug-stack-depth.md](../project/2026-09-26-debug-stack-depth.md). Standard library only; runs sandboxed. |
| `agent-trail` | `scripts/agent-trail <transcript.jsonl> <out.md>` condenses a subagent's JSONL transcript (the harness's `tasks/<id>.output`) into its own messages and tool calls, in order — the "predecessor trail" a fresh agent reads to continue a stopped agent's worktree without restarting (gotchas 2026-09-27). Standard library only. |
| `tree-expand-times` | Times `woodcase tree --json --expand` (or the plain read, `--no-expand`) once per fixture under a per-file timeout, slowest first; `--out <dir>` saves each file's rows as canonical JSON, so two sweeps — before and after a change to the tree read — diff with `diff -r`. See [project/2026-09-27-expanded-tree-cost.md](../project/2026-09-27-expanded-tree-cost.md). Standard library only; needs a built `woodcase`. |
| `migrate-pen` | Rewrites `.pen` files to the current format version in place, via `woodcase migrate`. |
| `mae-check` | Pre-commit hook step: compares MAE (mean absolute error) test results against the baseline and warns on regressions. Always exits 0. |
| `perf-binary` | Times `woodcase tree`/`set`/`shot` end to end, minimum of N runs, for a `--config debug` or `--config release` build. Information beside the in-process budgets in `Tests/WoodcaseTests/Performance/`; the in-process budgets are the release figures now that `swift test -c release` runs, and this measures what they cannot — process start-up. See [WoodcasePerformance](../Sources/Woodcase/Documentation.docc/WoodcasePerformance.md). |
| `soak-tests` | Runs the full suite N times and logs one result line per run, optionally against synthetic CPU load (`--load 2`). The suite's flakes are load-shaped, so "is it fixed?" is answered by a soak, not by one green run. A run that prints no summary is reported as `NO-SUMMARY` — that is what an out-of-memory kill looks like. See [project/2026-08-30-suite-stability.md](../project/2026-08-30-suite-stability.md). |
| `time-profile` | Records one or more runs of a command under Instruments' Time Profiler (`xctrace`), symbolicates the SwiftPM binary from the `.dSYM` beside it, and prints the functions with the most samples — inclusive, self, and with `--callers <name>` who calls them. `--copy <file>` gives a writing verb a fresh copy each run (`@` in the command). Found the per-line `Regex` in the file writer. See [WoodcasePerformance](../Sources/Woodcase/Documentation.docc/WoodcasePerformance.md). |
| `viewer-contrast` | Walks the viewer's preview catalog with `sleepy contrast` in both colour schemes and collapses ~3 300 text nodes into the distinct ink-on-ground *pairs* that fail, worst first — the shape a palette decision is made from. Feed it `woodcase preview --list` on stdin, pass `--base` the running server. Reproduces the table in [DESIGN.md](../DESIGN.md) § *Colors*; needs `sleepy` and the sandbox disabled. |
| `test-mae-check` | Regression test for `mae-check` itself. |
| `test-swiftui-api` | Regression test for `swiftui-api audit`'s verdicts — missing, deprecated, above the floor, `@available` gates, `@only` scopes, unavailable platforms — against a small hand-written corpus; needs no SDK. |
| `test-pen-validate` | Regression test for `pen-validate`'s PASS/FAIL classification and `--allow-unknowns`, against a stub `pen` CLI — it never depends on the real one. |
| `swift-di-miscompile` | Compiles and runs a 40-line case that the Swift optimizer gets wrong at `-O` — an unguarded release of a declared-but-unassigned local `var` in a generic function. Exits 0 while the toolchain is still broken, 1 once it is fixed and the workaround in `PenTextMeasurerFontCacheTests.undisturbed` can be retired. See [project/2026-08-30-release-only-ctfont-sigtrap.md](../project/2026-08-30-release-only-ctfont-sigtrap.md). |

Reproduces the micro-benchmark in [WoodcasePerformance](../Sources/Woodcase/Documentation.docc/WoodcasePerformance.md) § *Text measurement typesets once*. It starts where the ink centroids align and then minimises MAE on finer and finer grids. It prints that origin beside the ink-centred, advance-centred and line-box-centred predictions and their residuals, along with the font's ascent, descent and advance per em. | `blur-sigma-fit` | Fits the Gaussian sigma of a blurred edge in a PNG — a background-blur or layer-blur probe, Pen's own export or a Woodcase render — by least-squares grid search against the closed-form Gaussian-CDF edge model (`0.5·(1 − erf((x + 0.5 − c)/(σ√2)))`), fit against both the encoded sRGB row and its linear-light conversion. Reproduces Appendix A3 of [project/2026-09-26-pen-1.2.14-compatibility.md](../project/2026-09-26-pen-1.2.14-compatibility.md) (findings 6, 8, 10); with `--radius`, also prints Pen's expected `radius·scale/2` sigma and whether the fit is within 10% of it (the fitted-sigma criterion for leaf Gusv9b). Standard library plus AppKit/CoreGraphics (macOS only, like `probe-pixels.swift`); runs sandboxed for a fixture already inside the worktree, needs the sandbox disabled for a file elsewhere. |

See [project/2026-09-26-swiftui-codegen-feasibility.md](../project/2026-09-26-swiftui-codegen-feasibility.md) §2–3. Standard library only; `fetch` needs Xcode and the sandbox disabled. |
| `swiftui-fixture-probe.swift` | Renders hand-written SwiftUI — written the way a SwiftUI emitter would — for `render-text`, `render-gradients`, `layout-justify-space-between` and `layout-nested` with `ImageRenderer`, and prints each render's MAE against Pen's PNG, with the variants that show what a choice costs (default gradient interpolation vs `.colorSpace(.device)`, automatic vs pinned-off optical sizing, `Spacer` vs a custom `Layout`). ## Worked examples

`pen-validate`, against a passing fixture — the CLI's own `save()` bumps the declared
version (this CLI is now 0.3.9, which serialises 2.19; see the note below the table in
[project/2026-09-26-pen-1.2.14-compatibility.md](../project/2026-09-26-pen-1.2.14-compatibility.md)
about which engine produced which evidence):

```
$ scripts/pen-validate Tests/WoodcaseTests/Fixtures/blur1.pen
PASS Tests/WoodcaseTests/Fixtures/blur1.pen
  ~ /version: "2.17" -> "2.19"
```

Against a deliberately invalid fixture, the validator's own message comes through:

```
$ scripts/pen-validate Tests/WoodcaseTests/Fixtures/parser-unknown-properties.pen
FAIL Tests/WoodcaseTests/Fixtures/parser-unknown-properties.pen
  [INFO] Starting pen.dev (headless)...
  [ERROR] Document is not valid:
  - /children/1/type - expected one of: "frame", "group", "rectangle", "ellipse", "line", "polygon", "path", "text", "connection", "note", "context", "prompt", "icon", "script", "browser", "ref", got "video_clip"
  [ERROR] Error loading scene graph: Error: Node 'future-node' has no type
  [ERROR] Fatal error: Error: Failed to open document: …/parser-unknown-properties.pen
```

That fixture is *deliberately* invalid — it exists to prove Woodcase preserves properties and
node types Pen itself would drop — so a hand run over it passes `--allow-unknowns`, which PASSes
a file whose every reported violation is an unrecognized property or an unrecognized
enum/node-type value (still printing them, for visibility) and skips the diff, since Pen never
produced a re-saved file to diff against:

```
$ scripts/pen-validate --allow-unknowns Tests/WoodcaseTests/Fixtures/parser-unknown-properties.pen
PASS Tests/WoodcaseTests/Fixtures/parser-unknown-properties.pen
  --allow-unknowns: validator reported 4 error line(s), all unrecognized properties/types — allowed
  [ERROR] Document is not valid:
  - /children/1/type - expected one of: "frame", "group", "rectangle", "ellipse", "line", "polygon", "path", "text", "connection", "note", "context", "prompt", "icon", "script", "browser", "ref", got "video_clip"
  [ERROR] Error loading scene graph: Error: Node 'future-node' has no type
  [ERROR] Fatal error: Error: Failed to open document: …/parser-unknown-properties.pen
  (no re-saved output: Pen's engine did not load this document)
```

Without the flag, a file whose validator error list is non-empty still FAILs even when Pen's
engine tolerates the violation and saves the document anyway — the bug this script used to have,
where a clean exit code and a non-empty output file were mistaken for the validator's approval.

`blur-sigma-fit`, on `blur1.png`, the committed Pen.app 1.2.7 reference export of
`blur1.pen` (`radius: 10` at export scale 1; row 100 sits inside the background-blur box).
Pen's σ ≈ 4.6 here is the report's figure for Pen; finding 6's σ = 10.0 is Woodcase's own
render of the same row, before the blur-fidelity fix:

```
$ scripts/blur-sigma-fit Tests/WoodcaseTests/Fixtures/blur1.png --row 100 --x1 60 --x2 140 --channel r --radius 10 --scale 1
blur-sigma-fit: Tests/WoodcaseTests/Fixtures/blur1.png
  row 100, x 60..140, channel r
  sRGB   fit: c=100.00  sigma=4.570 px (4.570 pt at scale 1)  rms=0.0036
           expected sigma = radius*scale/2 = 5.000 px, ratio 0.91x (PASS, tolerance 10%)
  linear fit: c=98.85  sigma=4.413 px (4.413 pt at scale 1)  rms=0.0046
           expected sigma = radius*scale/2 = 5.000 px, ratio 0.88x (FAIL, tolerance 10%)
```

The two colorspace fits disagree here because this row also crosses the blurred box's own
semi-transparent white fill (`#ffffff80`), whose alpha blend entangles with the
sRGB-vs-linear question the fit is trying to isolate — a plain black/white edge fits
cleanly in whichever colorspace the blur actually ran in, and disagrees sharply in the
other (confirmed against a synthetic `CIGaussianBlur` step edge with a known radius, which
this tool recovers to within a few percent when fit in the colorspace Core Image actually
blurred in). Prefer a plain, high-contrast edge outside any translucent overlay when
picking a row to fit.
